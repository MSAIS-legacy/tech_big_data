# Решения заданий для варианта 26

Каждое решение находится в отдельной папке `I`–`VIII`.

## Выбор вариантов

Циклический номер вычисляется как `((26 - 1) mod M) + 1`, где `M` — количество применимых вариантов в задании.

| Задание | Число вариантов | Использован |
|---|---:|---:|
| I | 11 | 4 |
| II | 11 | 4 |
| III | 12 | 2 |
| IV | 12 | 2 |
| V | 11 | 4 |
| VI | 12 | 2 |
| VII | 15 | 11 |
| VIII | 12 применимых конвейерных вариантов | 2 |

В `VIII.pdf` после 12 конвейерных вариантов помещены формулы 14–26 от интегральной задачи: они не задают пару функций `f1` и `f2` и потому не являются вариантами конвейерного задания.

## Сборка

Требуются Windows, Visual Studio с компонентом «Разработка классических приложений на C++» и CMake:

```powershell
cmake -S . -B build -A x64
cmake --build build --config Release
```

Каждая программа печатает времена последовательной и параллельной реализаций и завершает работу с ненулевым кодом, если результаты расходятся. Для тяжёлых заданий параметры можно уменьшить аргументами командной строки; значения по умолчанию соответствуют условию или исходным примерам.

## GitHub Actions

Workflow `.github/workflows/run-all-tasks.yml` собирает проект через MSVC на `windows-latest` и запускает задания I–VIII с уменьшенными демонстрационными параметрами. Он запускается:

- вручную через **Actions → Build and run all assignments → Run workflow**;
- при изменениях решений или workflow в `main`;
- для pull request, затрагивающего эти файлы.

Вывод всех программ доступен на странице запуска в разделе **Summary**. Те же результаты сохраняются на 14 дней в артефакте `assignment-outputs` как отдельные текстовые файлы.

Для CI добавлены необязательные аргументы без изменения исходных значений по умолчанию:

- задания I и II: первый аргумент — число элементов, по умолчанию `2000`;
- задание VI: первый аргумент — размер сетки, второй — число членов суммы, по умолчанию `400 50`.
